## Scope

v0.3.1 is a runtime-correctness patch. It preserves the single-daemon architecture and does not expand Telegram write permissions.

### 1. Packaged `--url-domain` crash

Root cause: v0.3.0 relied on Python runtime codec lookup for `idna`; source Python could resolve it while a frozen PyInstaller `tgctl.exe` could miss the dynamically resolved codec/module.

Fix:

- explicit offline stdlib IDNA normalization;
- strict host/domain validation before Telegram work;
- exact-host/subdomain matching only;
- malformed input → structured `INVALID_ARGUMENT`;
- no public-suffix/network dependency;
- explicit PyInstaller `encodings.idna` hidden import as defense in depth;
- final standalone and portable `tgctl.exe` both execute the packaged search-filter smoke.

Coverage includes bare domain, `www`, mixed case, full URL, subdomain, whitespace, malformed host, empty results, suffix-lookalikes, pagination, and cursor query binding.

### 2. GUI normal-close fatal

Root cause: v0.3.0 could wait for Qt `aboutToQuit` and only then attempt asynchronous shutdown, after the qasync-backed event loop had already begun stopping.

Fix:

- coordinate cleanup from last-window-close before application quit;
- keep the Qt event loop alive while shutdown is pending;
- cancel/await GUI initialization and job-monitor tasks;
- cancel/await daemon-proxy heartbeat;
- detach the GUI lease only;
- do not shut down the shared daemon;
- allow the async app coroutine to return before Qt/qasync teardown;
- preserve logging/re-raising for genuine shutdown failures.

### 3. Sender / owner diagnostics

Sender classification uses Telegram-provided identity fields (`sender`, `from_id`, `peer_id`, `sender_id`, `sender_chat`, `post_author`, `via_bot_id`) rather than message text, links, titles, or display-name guesses.

Recoverable cases include user, channel/chat send-as, broadcast channel posts, anonymous admin, and deleted-user entities when Telegram still supplies a peer. `forward_origin` remains separate from the actual sender.

When Telegram does not provide enough information, the result stays `sender_type=unknown` with an explicit `unknown_reason` instead of inventing an identity.

Owner visibility now distinguishes permission/unavailability/pagination/Telegram-not-returned cases rather than collapsing all of them to `not_found`.

All new fixtures are synthetic/de-identified.

### 4. Bounded regex search

The acceptance matrix required `messages search` coverage for contains, regex, url-domain, sender, and sender-role. v0.3.0 had no regex parameter, so v0.3.1 implements it rather than falsely marking an absent capability as validated.

```powershell
tgctl messages search --chat <ref> --regex "release-\d+" --json
```

Semantics:

- local Python regex inside the existing bounded candidate scan;
- default case-insensitive; `--case-sensitive` switches behavior;
- composes with contains/domain/sender/sender-role/time/type/topic filters;
- empty/invalid/overlong regex → `INVALID_ARGUMENT` before Telegram work;
- max pattern length 512;
- regex + case sensitivity enter the HMAC cursor query fingerprint;
- a cursor cannot be reused with a different regex query;
- legacy schema rejects regex as a v3-only filter;
- source and final packaged standalone/portable smoke cover both regex and url-domain.

### 5. Acceptance-regression gaps closed

Additional synthetic tests now explicitly cover:

- `+08:00` vs UTC since/until boundary equivalence, preserving since-inclusive / until-exclusive semantics;
- two GUI leases coexisting with local tgctl status and sequential detach without daemon shutdown;
- zero-current-unread producing valid empty JSON without scanning full history or advancing read state;
- proxy privacy boundary: credential/query-bearing ProxyServer input is rejected, while normal safe labels contain endpoint metadata only.

## Remaining human acceptance

Automated validation is complete, but real Windows `%APPDATA%` state and the user's authorized Telegram account still require local checks before release readiness:

- packaged real-chat domain + regex search;
- idle GUI close;
- close after refresh;
- close after a zero-unread export with mark-read disabled;
- two GUI instances closed sequentially;
- `tgctl status` remains usable after GUI close and shared daemon remains alive;
- new log segment has zero normal-close Fatal/Traceback/un-awaited-task/Task-destroyed entries;
- same bounded sender sample is re-run and only before/after aggregate counts are reported;
- privacy audit reports counts only, never sensitive log contents.

No real send/forward, read acknowledgement, confirmed media download, group mutation, FloodWait stress, or Session reset is part of default acceptance. Those require separate explicit authorization.

Do not modify or overwrite the `v0.3.0` tag/Release. Do not create `v0.3.1` Release until human acceptance passes and the user explicitly authorizes merge/release.
