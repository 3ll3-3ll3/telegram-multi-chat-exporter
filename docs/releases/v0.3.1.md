# TG Exporter v0.3.1 Candidate Notes

Status: **candidate only — do not publish a Release yet**.

Base production: `v0.3.0` / `8e230e33ea928bcf71296e4e5379b097446dbec5`.
Development branch: `codex/v0.3.1-runtime-fixes`.

## Scope

v0.3.1 is a runtime-correctness patch release. It does not change the single-daemon security model and does not expand Telegram write permissions.

### 1. Packaged `--url-domain` crash

Root cause: v0.3.0 used Python's runtime codec lookup for `"idna"` while normalizing domains. The source environment had the codec, but the frozen `tgctl.exe` path could miss the dynamically resolved codec/module and fail inside domain normalization.

Fix:

- use an explicit, offline standard-library IDNA implementation;
- validate host/domain input before Telegram work;
- preserve exact-host or subdomain matching only;
- keep malformed input as structured `INVALID_ARGUMENT`, never `TELEGRAM_ERROR`;
- add an explicit PyInstaller `encodings.idna` hidden import as frozen-build defense in depth;
- run the search-filter smoke directly against both final standalone and portable `tgctl.exe`.

Regression coverage includes bare domain, `www`, mixed case, complete URL, subdomain, surrounding whitespace, malformed domains, no-match results, suffix-lookalikes, pagination, and cursor query binding.

### 2. GUI normal-close fatal error

Root cause: v0.3.0 waited for `QApplication.aboutToQuit` and then attempted asynchronous shutdown. By then Qt could already have stopped the qasync-backed event loop, so `run_until_complete` observed an unfinished future and raised `RuntimeError: Event loop stopped before Future completed`.

Fix:

- do not stop the event loop while shutdown is still pending;
- coordinate on last-window close before application quit;
- cancel and await GUI-local initialization/job-monitor tasks;
- cancel and await daemon-proxy heartbeat;
- detach the GUI lease from the shared daemon;
- let the async app coroutine finish normally before Qt/qasync teardown;
- preserve exception logging for real shutdown failures.

Normal GUI close does **not** request shared-daemon shutdown.

### 3. Sender and owner diagnostics

Sender classification now prefers Telegram-provided identity fields (`sender`, `from_id`, `peer_id`, `sender_id`, `sender_chat`, `post_author`, `via_bot_id`) and does not infer identity from message text, links, or display-name guesses.

Recoverable cases include user, channel, chat, broadcast-channel posts, anonymous-admin/send-as, and deleted-user entities when Telegram still provides a user peer. Forward origin remains separate from the actual sender.

When Telegram does not provide enough information, `sender_type=unknown` is retained with an explicit `unknown_reason`, including:

- `service_message_without_sender`
- `forwarded_message_without_actual_sender`
- `post_author_without_sender_peer`
- `unsupported_or_unavailable_sender_peer`
- `telegram_sender_not_provided`

Owner visibility now distinguishes states such as insufficient permissions, participant-list unavailability, creator not appearing in the bounded returned page, Telegram not returning a creator, and genuinely missing creator data where that conclusion is supportable.

All added fixtures use synthetic names/IDs and contain no real Telegram data.

### 4. Bounded regex search completion

The v0.3.1 acceptance matrix explicitly requires `messages search` regression coverage for `contains`, `regex`, `url-domain`, sender, and sender-role. v0.3.0 did not actually expose a regex parameter, so v0.3.1 adds it rather than claiming an unimplemented check passed.

```powershell
tgctl messages search --chat <ref> --regex "release-\\d+" --json
```

Semantics:

- Python regex, applied locally inside the existing bounded candidate scan;
- default case-insensitive, with `--case-sensitive` using exact case;
- regex can be combined with contains/domain/sender/sender-role/time/type/topic filters;
- invalid or empty regex returns structured `INVALID_ARGUMENT` before Telegram work;
- pattern length is capped at 512 characters;
- regex text and case-sensitivity are part of the HMAC cursor query fingerprint, so a cursor cannot be reused across a different regex query;
- legacy-schema search rejects regex as an unsupported v3 filter.

CI includes source tests plus an offline regex/domain smoke directly against the final packaged standalone and portable `tgctl.exe`.

## Remaining human acceptance

Before calling v0.3.1 release-ready, use a real authorized local account only within the existing safety boundary and verify:

- domain and regex search on a real chat with the packaged `tgctl.exe`;
- idle GUI close, close after refresh, close after a zero-unread export, and two-GUI sequential close;
- `tgctl status` remains usable after GUI close;
- no normal-close Fatal/Traceback/un-awaited-task/Task-destroyed entries in the new log segment;
- sender unknown classification statistics on the same bounded sample used for the v0.3.0 finding;
- no actual send/forward, read acknowledgement, or media download unless the user separately authorizes it.

Do not modify or overwrite the `v0.3.0` tag or Release. Do not create `v0.3.1` Release until explicit user authorization after human acceptance.
