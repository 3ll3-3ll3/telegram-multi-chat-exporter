# TG Exporter v0.3.0 — Candidate Notes

> **未发布。** 本文记录第三代 candidate 范围。未经用户真实账号验收与明确发布授权，不创建或覆盖 GitHub Release `v0.3.0`。

## 核心变化

v0.3.0 在 single-daemon / Windows Named Pipe IPC 基础上增加 Personal Account Reader，并且在真人 E2E 前已把正式 `main@v0.1.10` 纳入 ancestry。PR #20 现在直接以 `main` 为 base，因此用户测试的是正式线集成后的运行候选。

```text
TGExporter GUI ─┐
               ├→ TG daemon → Telegram user Session
tgctl / Codex ─┘
```

GUI 与 tgctl 不再各自 direct-open SQLiteSession；正常 v0.3 GUI + v0.3 tgctl 可以同时存在。

## 新 Reader 命令

```text
tgctl account get
tgctl dialogs list
tgctl chats get
tgctl chats members
tgctl messages history
tgctl messages search
tgctl messages get
tgctl topics list
tgctl topics history
tgctl media download
```

`dialogs list` 增加 private/bot/Saved Messages/archive/forum 等完整账号会话视角，同时保留 GUI-oriented `chats list` 兼容。

## Pagination / migration

- default 100 / max 500；
- HMAC/query-bound opaque cursor；
- dialogs canonical stable order；
- history newest→older；
- Basic Group→Supergroup logical history current→legacy；
- migration unique key `(source_chat_id,message_id)`；
- global migrated advanced-search legacy cursor 已修复，分页不会因忽略 segment 而重复/遗漏；
- single-chat migrated search 会校验 cursor segment，迁移关系失效时返回 `CURSOR_STALE`；
- migrated rich-get 保持 current logical `chat_id` 与 legacy `source_chat_id` 分离。

## Rich message / identity

Reader 结果增加 structured sender、reply、forum topic、forward origin、entities、views/forwards、reactions、poll、service action、media metadata 等安全字段。

owner/admin/member 基于 Telegram 当前 participant/admin snapshot，不通过显示名猜。匿名管理员/send-as 不反推隐藏用户。读取 legacy Basic Group 历史时，current-role snapshot 仍基于当前逻辑 Supergroup entity。

## Advanced search

支持 single/global、contains、sender-id、current sender-role、since/until、message type、topic、link、真实 URL domain、cursor/limit、JSON/JSONL。

`--url-domain mypikpak.com` 使用 hostname parsing；`mypikpak.com.evil.com` 不匹配。

## Forum

支持 Topic list/history。Telethon 1.44 使用 `messages.GetForumTopicsRequest(peer=...)`。

## Media

普通 reader 默认 metadata-only，不自动下载。

显式下载采用 plan → confirmation token → download：

- 第一次不创建目录、不下载；
- normal 20 files / 500 MiB；
- explicit large 最大 200 files / 5 GiB；
- safe basename/path handling；
- `.part` → atomic rename；
- confirmed transport outcome 不自动 retry。

## Compatibility / safety

保留旧 `status/chats list/messages search/messages get/forward/send`；rich get/search 提供 legacy schema 过渡选项。

现有 write safety 不放松：true forward、plain-text send、dry-run、20/200 forward cap、AMBIGUOUS_CHAT、FloodWait structured stop、write outcome unknown no retry、export 时 real write 拒绝。

v0.1.10 Windows UTF-8 stdout 修复、cp1252 source regression、Session lock helper，以及 standalone + portable packaged `SESSION_BUSY` + native exit 8 gate 均已 forward-port。

v0.3 更严格禁止普通日志记录 `api_id/api_hash`、phone/OTP/2FA、Session/credentials、access_hash/file_reference、message body/caption/URL text/media filename。
